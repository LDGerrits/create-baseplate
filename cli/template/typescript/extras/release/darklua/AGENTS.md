## Release builds

`mise run publish` and the publish workflow build the release before they upload it; it's not part of the check, and the check and the hooks never run it. `mise run release` alone builds it: it compiles, processes the compiled code with Darklua into `dist/` by the rules in `.darklua.json` (minified, with dead branches and unused variables removed and locals renamed), builds `build/release.rbxl` from it, and runs the tests on that build. Publish `build/release.rbxl`, never `build/game.rbxl`: `mise run publish` builds the release and publishes it. Develop and debug on `mise run check` and `mise run dev`, which use the unprocessed code in `out/`: the release's error lines and names don't match the source, and processing is slow, so don't run `mise run release` while you work. Run it only when a publish fails on the release build: when the tests pass in `mise run check` and fail in `mise run release`, a Darklua rule broke the code: remove that rule from `.darklua.json`.
