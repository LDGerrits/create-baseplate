## Release builds

`mise run publish` and the publish workflow build the release before they upload it; it's not part of the check, and the check and the hooks never run it. `mise run release` alone builds it: it processes `src/` and the packages in `Packages/` and `ServerPackages/` with Darklua into `dist/`, by the rules in `.darklua.json` (minified, with dead branches and unused variables removed and locals renamed, and the UI stories left out), builds `build/release.rbxl` from it and runs the tests on that build. Publish `build/release.rbxl`, never `build/game.rbxl`: `mise run publish` builds the release and publishes it. Develop and debug on `mise run check` and `mise run dev`, which use the code as written: the release's error lines and names don't match the source, so run `mise run release` when you prepare a release or when a publish fails on it, not while you iterate. When the tests pass in `mise run check` and fail in `mise run release`, a Darklua rule broke the code: remove that rule from `.darklua.json`.
