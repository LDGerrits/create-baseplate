## Player data

`PlayerDataService` (`src/features/player-data/server/`) loads each player's saved data with Lapis (`@rbxts/lapis`) when they join, and saves it when they leave. Other services read it with `get(userId)` and change it with `update(userId, (data) => newData)`, getting the service through their constructor. To save a new field, add it to `PlayerData` and `DEFAULT_PLAYER_DATA` in `player-data.ts`, to `validate` in the service, and to a Lapis migration (`migrations` in `createCollection`'s options) that adds it to data saved before; Lapis rejects data `validate` doesn't accept, and the player can't load. Studio saves to a mock store, forgotten when the server stops, and specs give the service their own (`player-data-service.spec.ts`). Lapis moves only while physics runs, which an Open Cloud execution session (`mise run test:engine` in CI) doesn't do, so a spec that loads data is declared with `whileSimulating` instead of `it`, as that spec's are, and skips there.
