# create-baseplate

## 0.2.0

### Minor Changes

- 3c3e4a8: Darklua (`--release darklua`) now runs only when the game publishes: `mise run publish` and the publish workflow build and test the release, and the game's CI no longer does on every push. A partially managed game can't take it, since Studio publishes that game.
- 2a807e6: Code in a game is organised in four layers, in both languages, and the check enforces them: `app/` (entry scripts), `features/<feature>/` (what the game could ship without), `game/<system>/` (always-on systems) and `platform/<module>/` (game-agnostic code). Imports only go down, features never import each other in a cycle, side folders (`server/`, `client/`, `shared/`) sit only at `app/<side>/` and `<layer>/<module>/<side>/`, and modules of `game/` and `platform/` have names, not `utils` or `helpers`. A Luau game's requires are read through its sourcemap. The player data add-ons write `game/player-data` (`game/playerdata` in Luau), Asphalt writes its IDs to `game/assets/shared`, and Reflex's store sits in `game/store/`.
- cf9b665: The guard now covers Roblox Studio's MCP server: it blocks `open_cloud_invoke`, and `execute_luau` that reaches DataStores, MemoryStores, messaging or HTTP, in every agent tool. The check fails on unions, `SurfaceAppearance` and wrap layers, which Open Cloud's place publishing doesn't update. AGENTS.md asks agents to look at what's there before changing it, and to follow the code where AGENTS.md disagrees with it.
- 5ece739: Luau games declare their remotes with Remo instead of the template's own `Remote`, `Serve` and `RateLimit` modules: each feature's remotes sit in a Remo namespace, with a `t` validator for what clients send and `throttleMiddleware` on client-to-server remotes. The check still fails on `OnServerEvent` or `OnServerInvoke` in the game's own code.
- 4e65ce1: A new question, `--managed full|partial`, asks whether Rojo manages the whole place or only the code, after the places question and in both languages. `full`, the default, is as before: the map and lighting are files in `world/`, and the game builds and publishes from git. `partial` follows Roblox's partially managed workflow: Studio owns the place and its world, and files hold only the code. The game has no `world/`, `mise run sync`, `edit-world` skill, world types, `scripts/publish.ts`, `mise run publish` or publish workflow, and its `AGENTS.md` and `release` skill say that instances in the workspace aren't typed, that agents reach them with `WaitForChild` and look at or change the map through the Studio MCP, and that the user publishes from Studio. `mise run dev` compiles on save and serves the code with Rogen, and opens no Studio: open your place and connect the Rojo plugin. The check and the tests run on a place made of the code alone; with `--entities jecs` or `components`, the spinner's end-to-end test makes its own part. `create-baseplate sync` keeps a partially managed game without the world's files.
- e9a4bd9: A Luau game now starts as small as `rojo init`'s: the clicker example, the UI root and its end-to-end tests are gone. `src/app/server/Main.server.luau` and `src/app/client/Start.luau` start with empty lists of services and controllers, `src/features/` appears with your first `mise run feature <name>`, and the world keeps a baseplate, a spawn and the lighting. React or Vide stays installed, and `AGENTS.md` says how to mount a UI root; Charm and Vide add only their packages and their notes in `AGENTS.md`. The check, the hooks, the skills and the test and story runners are unchanged, and pass with nothing to run.
- c0489e9: A TypeScript game now starts as small as `rojo init`'s: Flamework ignited in the two entry scripts (`src/app/server/main.server.ts` and `src/app/client/main.client.ts`), no services, controllers or UI, and a world with a baseplate, a spawn and lighting. The clicker example, the UI root, `react-dev.ts` and the rate-limit middleware are gone, so there are no specs, end-to-end tests or stories until you add them. `mise run feature <name>` still starts a feature and imports it in the entry scripts. The check still fails on a client-to-server event with no middleware, now pointing you to Flamework middleware that rate-limits it, or to `// trusts-client: <why>`. `AGENTS.md`'s UI section shows how to mount a React or Vide root. `--state charm` and `--state reflex` add their packages and `AGENTS.md` section; `--ui vide` swaps the packages, the JSX settings and the lint config.
- fb8fe59: The CLI asks the project's shape first (how many places, and how much Rojo manages), then offers the recommended libraries and tools in one answer, with what they are, or asks about each one in turn. Flags still answer any question ahead of time.
- facd053: The publish workflow snapshots the game's DataStores before it publishes to prod, so players' data as it stood stays restorable for 30 days if a release corrupts it. Prod's key needs `universe-datastores.control:snapshot` as well.
- 075dac2: The state question now has a default: Reflex in TypeScript games and Charm in Luau games. A TypeScript game with Vide takes Charm, since Reflex has no Vide binding. Pass `--state none` for a game without a state library.

### Patch Changes

- 0db4ad7: A game's stop hook and commit hook no longer rerun the check on files it already passed on. The check records the state it passed (in the worktree's git folder, never committed); the stop hook skips when the files are the same, and the commit hook when what is staged is the same, so a check, a stop and a commit of one state cost one check, not three. A commit that stages only Markdown skips the check too. A pass of the working tree never lets a different staged state through: the commit hook compares the index, not the files on disk.
- 3f91465: Cursor's hooks now start through `.agents/hooks/run` like every other agent's, so when mise can't be found the guard still blocks publishing and Studio's live tools in Cursor, instead of letting them through. On Windows this needs `sh` on the PATH Cursor's PowerShell uses (Git for Windows' `usr\bin`).
- e1ad7c0: A game's `AGENTS.md`, README and docs say what the faster check and hooks do: about three seconds, one run per state, an ESLint server for the edit hook, and the troubleshooting entries for skipped hooks and the server.
- 6874e1e: A game's CI runs its specs in real Roblox (the engine job) only on main and when run by hand, not on every pull request, so pull requests stay fast and don't spend the Open Cloud quota or the test place's DataStores.
- 4f5ef40: In a TypeScript game, the hook that formats and lints each file an agent edits takes about 0.2 seconds instead of 1.9 after the first edit. The first edit starts a small server that keeps ESLint loaded (`.agents/hooks/eslint-server.ts`, one per project, stopped after ten idle minutes); it restarts when anything but the edited file changed, so it never answers from stale types, and the hook lints in its own process whenever the server can't be used.
- e13b92c: A game's CI installs the software Vulkan driver for UI pictures without refreshing apt's package lists first, unless the install needs it, which takes about 15 seconds off each run.
- 62f9239: When the first commit of a new game fails, because its hook's check fails, the CLI now exits with 1 and says so (with `--json`, `"ok": false` and an `error`), instead of exiting 0 with a warning. The game stays in its folder, uncommitted, and the next steps end with the commit to run.
- c5803a2: When the agent guard can't run, because mise is missing or the hook fails, it still blocks Studio's live tools and publishing instead of letting them through. Other calls still go through.
  
  The place check now warns about unions, `SurfaceAppearance`, wrap layers and editable images and meshes instead of failing: Open Cloud's place publishing doesn't update them, so after changing one, publish from Studio. In Cursor, the guard on MCP calls no longer refuses other MCP servers started with `npx`.
- f997dc2: A game's README, `AGENTS.md`, skills and the docs now match what the code does: the guard's scope and its fallback when it can't run, which key prod publishes with, when the engine job runs, how the Darklua release is run, how to build a Remo request, and, in partially managed games, how to install Rojo's Studio plugin and which tools run where. In a multi-place Luau game, Darklua's section names the folders it processes.
- 361d6d2: A game's CI runs on main are no longer cancelled by a later push, so a version tag on a commit that is not main's newest still finds its CI result and publishes; only a pull request's older run is cancelled.
- cfb72b0: A game's checks no longer leave temp files behind: the tests of `mise run feature` remove the folders they make, and the edit hook keeps Node's compile cache in `node_modules/.cache` instead of the system temp folder, where each checkout added about two thousand files that nothing removed.
- 47043a0: A game's check lists its formatting step once, with the form that fixes files beside the form that only checks, and its hooks share one definition of a Markdown file.
- 85b2aeb: A TypeScript game's lint reports a number or string used as a condition once, by `strict-boolean-expressions`, instead of also by `roblox-ts/lua-truthiness`, whose message told agents to turn the rule off in `eslint.config.ts`. The comment on the rule now says what roblox-ts does with `0`, `""` and `NaN`: it keeps JavaScript's falsiness by adding checks to the Luau.
- acc39fc: `mise run check` runs the steps that don't need each other's result at the same time, and in a multi-place game the places too, so the slowest step bounds it: about 3 seconds instead of 7 (TypeScript and Luau alike). It prints only the output of a step that failed, in a fixed order, then one line saying how it went. `mise run ci` is the same list of steps without the fixes (`scripts/check.ts`), where it used to be a copy. The tooling's own type-check and tests (of `scripts/` and `.agents/hooks/`) run only when those files changed since they last passed, and always on CI.
- 72faef5: A game's publish workflow publishes a version tag to stable or prod only when the tagged commit's CI passed on main, waiting for a run that is still going.
- 71bcb0e: The check refuses folders named `util`, `utils`, `lib` or `libs`, in any case, in `features/`, `game/` and `platform/`; `helpers`, `common` and `misc` are allowed.
- 41d78bd: Claude Code, Codex and Cursor no longer start Rogen's own stop hook beside the check, which ran `rogen check` a second time at every stop. The file `.agents/hooks/rogen-check.mjs` stays as Rogen writes it; only the wiring in `.claude/settings.json`, `.codex/hooks.json` and `.cursor/hooks.json` is gone.
- f01f5dc: Prod publishes from a tag even when the game has no stable target: before, a skipped stable job held prod back too. The docs now say most games need only dev and prod, and stable is for releases other people test first.
- baa0f80: The `drive-studio` skill no longer names Studio's skill tools, which Roblox renamed, and keeps agents on ree rather than Studio's `rbx-unit-test`.
- 538ab6a: A game's check now fails on a Roblox API used on the wrong side: client-only ones (`Players.LocalPlayer`, `UserInputService`, `RunService.RenderStepped`, `StarterGui:SetCore` and others) in `server/` code, and server-only ones (`DataStoreService`, `MessagingService`, `MemoryStoreService`, `ServerStorage`, `ServerScriptService`, `HttpService:RequestAsync`, `BadgeService:AwardBadge`, `MarketplaceService.ProcessReceipt` and others) in `client/` code. Both apply in `shared/`, where a call guarded by `RunService` is allowed with a disable comment (TypeScript) or `-- guarded: <why>` (Luau). TypeScript games use ESLint rules, Luau games the source check.

## 0.1.0

### Minor Changes

- d8d1566: A game's agent files (`AGENTS.md`, skills, hooks and the agent tools' settings) now keep up with create-baseplate. `package.json`'s `baseplate.version` pins the version they come from; Renovate updates it, and the game's `.github/workflows/renovate-fixups.yml` (formerly `mise-lock.yml`) runs the new `create-baseplate sync` on its branch, which brings the files up to that version and merges in the game's own edits, as git would. An edit that clashes leaves the template's version beside the file as `<file>.baseplate-new`, and the check fails until it's merged. `.baseplate/agent-files.json` records the base of that merge.
- 41c2c40: The guard and the stop check now run in GitHub Copilot (cloud agent and CLI, `.github/hooks/checks.json`) and Gemini CLI (`.gemini/settings.json`, which also points Gemini at `AGENTS.md`), as well as Claude Code, Codex and Cursor. Hooks start through `.agents/hooks/run`, which finds mise in `~/.local/bin` too and lets the agent carry on when mise is missing. The stop check skips its run when nothing changed since the last pass, and in Cursor it no longer restarts the agent after you press Stop. `.agents/hooks/cloud-setup.sh --force` sets up Cursor's cloud agents (`.cursor/environment.json`), Codespaces (`.devcontainer/devcontainer.json`) and Codex cloud; the Copilot setup steps install the Vulkan driver the UI check needs. Claude Code no longer asks before the `forge`, `ror` and `rogen` commands the skills use, and `mise run install` restores the `.claude/skills` link on Windows clones without symbolic links.
- 38f7d41: `mise run feature <name>` starts a feature: its network file, a service with every client-to-server event behind `rateLimit` and a spec, a controller, and their imports in the entry scripts (in a multi-place game, in the shared code, or in one place when you name it). New `add-feature`, `release` and `upgrade` skills tell agents how to build a feature, make a release ready for the user to publish, and handle a Renovate update or a `.baseplate-new` file.
- 1bea0eb: `create-baseplate doc [topic]` prints a page of Baseplate's docs as Markdown, the version it ships, and lists the topics without one; `--json` for agents. In a game, `mise run doc <topic>` runs it at the version `package.json`'s `baseplate.version` pins, and `AGENTS.md` points agents to it. `create-baseplate doc` no longer creates a game in a folder named `doc`; write `./doc` for that.
- d27ebbe: Agents get lint feedback after each file edit, not only when they stop. A new hook, `.agents/hooks/edited.ts`, formats the edited file with Biome, applies ESLint's fixes to it and hands the lint problems left straight back to the agent, in Claude Code, Codex, GitHub Copilot and Gemini CLI; in Cursor it applies the fixes without a message. It leaves alone what the agent is still writing: an import not used yet stays, as does a `let` and a value import. It lints only the edited file, in two to three seconds, and leaves the compiler to the stop check.
- b87ff08: First release: create a roblox-ts game set up for coding agents, with add-ons for the UI library, places, state, player data, entities, assets and release builds.
- ac7ca58: A game's `AGENTS.md` now opens with "Look it up, don't recall it": it tells agents their memory of roblox-ts, Flamework, Rogen and the Roblox API is likely out of date, and points them at docs that match the installed versions: the doc comments in `@rbxts/types` (with links to Roblox's Markdown docs), the installed packages' `.d.ts` files and READMEs, and `rogen doc`. Charm, Jecs and Vide add where their own docs are.
- bcd0c24: Make Luau games: the first question is now the language, `--language typescript` (roblox-ts, the default) or `--language luau`. A Luau game has its own template with the tools Luau developers use: Wally for packages, StyLua, Selene, and luau-lsp type-checking every file in strict mode against every instance in the game, world included. It keeps the same agent setup as a roblox-ts game: one `mise run check`, the hooks and skills, Jest specs and end-to-end tests in ree, story pictures in rur, and the commit hook. Services and controllers are plain modules, and remotes are declared once with a `t` check and taken by the server only through a rate limit. Its add-on questions offer what Luau games use: React or Vide, one place or several, Charm, ProfileStore or Lapis, Jecs, Asphalt and Darklua. Games record their language in `package.json`, so `create-baseplate sync` updates their agent files from the right template; games made before this are TypeScript.
- 9d207f5: Games publish from git. `mise run publish` builds the place and publishes it through Open Cloud, and the new `publish.yml` workflow publishes main to a dev place, a version tag to a stable place, and the same tag to the live game once someone approves it. Agents can't publish: a hook stops them. The `edit-world` skill now covers art and unions saved as `.rbxm`, source art in Git LFS, placing many copies of one asset with markers, and what `forge restart` drops.
- 1cd5bb1: `mise run check` now fails when the server takes a client-to-server event or function without middleware, naming the remote and its file: missing server-side checks on remotes are how Roblox games get exploited, and Flamework's types allow them. The game ships `rateLimit` and `rateLimitFunction` in `src/network/server/rate-limit.ts` (`projects/common/src/network/` with `--places multi`), middleware that drops a player's calls beyond a number a second; the clicker example uses it, and its service still applies its own cooldown. A remote that any client may send freely is marked `// trusts-client: <why>` on the line above its handler.

### Patch Changes

- 49d354f: A game created with `--no-install` and an add-on that brings a tool (Asphalt, Darklua) is no longer committed with a `mise.lock` that lacks the tool; the next steps say to commit after `mise lock` and the install. `mise run ui` renders the stories without Studio's fonts, as in a cloud session, instead of refusing; the pictures show layout without text. The `drive-studio` skill connects the Studio MCP the way Roblox's docs say (Quick connect) and keeps agents from editing scripts, saving or inserting assets through it. `AGENTS.md` names `mise run compile` as the fastest loop for type errors.
- 124e066: `--release darklua`: `mise run release` leaves the UI stories out of `dist/`. They were processed into it, and `mise run check` then tried to render the minified copies and failed until `dist/` was deleted.
- 7d4ccdb: `mise run test:engine` now runs in a real Roblox server. The place it uploads is built from `test.project.json`, the game with `loadstring()` on, which Jest needs; the game itself keeps it off. With Lapis, the specs that load data skip in an Open Cloud session, where Lapis can't move because physics doesn't run.
- 176d794: Luau games use lowercase folders, as Rogen's own starter does: `src/app`, `src/network` and `src/features/<feature>`, each with `server/`, `client/` and `shared/`, and routes spelled the same in `default.rogen.json`. Files keep their PascalCase names. A required module's path changes with its folder, such as `ServerScriptService.features.clicker.ClickerService`.
- d554c60: The npm page lists keywords (roblox-ts, rbxts, roblox, scaffold, agents, claude-code, codex, cursor), so the package turns up in searches.
- ef07fa0: Games use Rogen 2.0.0-rc.1. Its rules in `AGENTS.md` and its hook, `.agents/hooks/rogen-check.mjs`, are Rogen's own now, so `rogen write` no longer rewrites them, and Biome leaves the hook alone. A Luau game's routes are spelled `Server`, `Client` and `Shared`, like its folders, since Rogen now routes only a folder or `@` suffix spelled exactly as its key.
- 47b12d8: Games use Rogen 2.0.0-rc.2. The rules in `AGENTS.md` name lowercase routes, such as `shared/server/Save.luau`, as Rogen now writes them.
